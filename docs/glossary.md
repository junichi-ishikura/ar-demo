# 用語解説（知らない前提で読む）

README や仕様書に出てくる言葉を、Web や 3D の知識がない前提で説明します。
上から順に読むと、このデモが「何を使って、どう動いているか」がつながります。

---

## 1. Webページの基本

### HTML / CSS / JavaScript
- **HTML**: ページの「中身」を書くファイル。見出し、文章、ボタン、画像などを並べる。拡張子は `.html`
- **CSS**: ページの「見た目」を決めるファイル。色、大きさ、配置など。このデモでは `style.css` 1つにまとめている
- **JavaScript（JS）**: ページを「動かす」プログラム。ボタンを押したら何かする、カメラを起動する、など。拡張子は `.js`

このデモの `config.js` も JavaScript ですが、「設定値を並べただけ」のファイルなので、プログラムを知らなくても数字や文字を書き換えられます。

### 静的サイト
サーバ側で計算をせず、置いてあるファイルをそのまま配るだけのサイト。GitHub Pages のような無料サービスで公開できます。このデモは静的サイトです。

### CDN（シーディーエヌ）
よく使われるプログラム部品（ライブラリ）を、インターネット上の共有サーバから直接読み込む仕組み。
このデモは A-Frame や MindAR などを CDN から読んでいるので、**自分のパソコンにライブラリをインストールする必要がありません**。ただし、ネットにつながっていないと動きません。

「バージョンを固定する」というのは、CDN の URL に `@1.2.5` のように番号を書いて、「常にこの版を使う」と決めることです。番号を書かずに最新版を指すと、ある日勝手に中身が変わって動かなくなることがあります。

### HTTPS
URL が `https://` で始まる、暗号化された通信。スマホのブラウザは **https でないとカメラを使わせてくれない**ので、AR デモは https で開く必要があります。GitHub Pages は最初から https です。手元のパソコンで試すときは「トンネル」や「自己署名」という方法で https にします（リポジトリの README 1-1）。

### GitHub Pages
GitHub に置いたファイルをそのままWebサイトとして公開してくれる無料サービス。設定画面でオンにするだけで `https://ユーザー名.github.io/リポジトリ名/` で見られるようになります。

## 2. 3D と AR の基本

### AR（拡張現実）
カメラに映った現実の映像の上に、3D モデルや文字を重ねて表示する技術。このデモには 2 種類の AR があります。

| 種類 | 何を目印にするか | このデモでの使いどころ |
|---|---|---|
| **画像マーカー AR** | 紙に印刷した「絵（マーカー）」 | デモA・B。絵の上に 3D や情報が出る |
| **平面配置 AR** | 「床」などの平らな面 | デモC。床に等身大のモデルが立つ |

### マーカー（画像マーカー、ターゲット画像）
カメラに「これを探せ」と覚えさせる絵のこと。AR ソフトは、絵の中の「特徴点」（角や模様の変わり目）を頼りに、絵がどこに・どんな角度であるかを追いかけます。

だから、**特徴点の多い絵**（模様が細かく、白黒のコントラストが強く、左右対称でない絵）ほど認識しやすく、**のっぺりした絵**（単色、細い線だけ、同じ模様の繰り返し）は認識できません。`tools/make-markers.mjs` はこの条件を満たす絵をランダムに作るスクリプトです。

### 3D モデル / glb / usdz
- **3D モデル**: 立体の形と色（テクスチャ）のデータ
- **glb**: 3D モデルの標準的なファイル形式（glTF 形式を1ファイルにまとめたもの）。Android やブラウザで使う
- **usdz**: Apple が iPhone 用に決めた 3D ファイル形式。**iPhone で「床に置く」AR をするには usdz が必須**
- なので、デモC のモデルは **glb と usdz の両方**を同じ名前で置いています（`monument.glb` と `monument.usdz`）。glb から usdz への変換が `tools/usdz-convert.html` の役目です

### テクスチャ
3D モデルの表面に貼る「画像」。木目や金属の質感はテクスチャで表現します。usdz 変換に失敗すると「形はあるのに真っ白／真っ黒」になりますが、それは形は変換できてテクスチャが落ちた状態です。

### アニメーション（glb 内蔵アニメ）
glb ファイルの中には「歩く」「見回す」といった動きのデータを入れられます。今のデモA のキツネ（`fox.glb`）には `Survey`（見回す）`Walk`（歩く）`Run`（走る）の 3 つが入っていて、`config.js` の `animation` で選べます。動きが入っていないモデルの場合は、代わりにくるくる回転させています。

### ポリゴン数
3D モデルは小さな三角形（ポリゴン）の集まりでできています。数が多いほど細かい形になりますが、ファイルが重くなりスマホで遅くなります。スマホ AR では数千〜数万程度が目安です。

## 3. このデモで使っているライブラリ

### A-Frame（エーフレーム）
**ブラウザで 3D を表示するための部品セット**です。本来、ブラウザで 3D を出すには three.js というライブラリを使って長いプログラムを書く必要がありますが、A-Frame を使うと HTML のタグを並べるだけで 3D の場面（シーン）を作れます。

たとえば、こう書くだけで 3D 空間に赤い箱が出ます。

```html
<a-scene>                                  <!-- 3D の舞台 -->
  <a-box color="red" position="0 1 -3"></a-box>   <!-- 赤い箱を、少し上・少し奥に -->
</a-scene>
```

タグの名前が `a-` で始まるのが A-Frame の部品です。主なもの:

| タグ | 意味 |
|---|---|
| `<a-scene>` | 3D の舞台全体。この中に部品を置く |
| `<a-entity>` | 「何か」を置くための空の入れ物。中に 3D モデルを入れたり、グループ化に使う |
| `<a-plane>` | 平らな板 |
| `<a-image>` | 画像を貼った板 |
| `<a-video>` | 動画を貼った板 |
| `<a-gltf-model>` / `gltf-model="…"` | glb（glTF）の 3D モデル |
| `<a-text>` | 文字（後述。日本語が出ない） |
| `<a-camera>` | 見る位置（カメラ）。AR ではスマホのカメラに合わせて自動で動く |

各タグには `position="x y z"`（位置）、`rotation="x y z"`（向き）、`scale="x y z"`（大きさ）を付けて配置します。`config.js` の `scale` や `yOffset` は、この値に流し込まれています。

### `<a-text>` とは
A-Frame で **3D 空間の中に文字を浮かべるためのタグ**です。

```html
<a-text value="Hello" color="black" position="0 1 0"></a-text>
```

ただし、`<a-text>` は文字を「フォントの画像（あらかじめ描いておいた文字の絵）」から組み立てる仕組みで、**標準で入っているフォントには英数字しかありません**。日本語を指定しても、文字が出ないか「□」になります。日本語フォントを自分で用意して変換して読み込ませる方法もありますが、手間が大きく、ファイルも重くなります。

そこでこのデモでは、`<a-text>` を使わずに次の方法で日本語を出しています。

1. ブラウザ内の「canvas（キャンバス）」という見えないお絵かき領域に、スマホの標準フォントで日本語を描く
2. できた絵をテクスチャとして `<a-plane>`（板）に貼る

これを部品化したのが `marker/ar-common.js` の `text-board` です。使い方は `<a-text>` とほぼ同じで、`<a-plane text-board="text: こんにちは; style: bubble">` のように書きます。仕様書では「`<a-plane>` + `<a-text>`」と書かれていましたが、日本語を出すためにこの方式に変えました（見た目の目的は同じです）。

### MindAR（マインドエーアール）
**画像マーカー AR を実現するライブラリ**です。カメラ映像の中からマーカーの絵を探し、見つかった位置に A-Frame の 3D を重ねます。無料・オープンソースで、スマホのブラウザだけで動きます。

MindAR に「この絵を探せ」と教えるには、絵をそのまま渡すのではなく、あらかじめ特徴点を抜き出した **`.mind` ファイル**（このデモでは `marker/targets.mind`）に変換（コンパイル）しておく必要があります。変換は MindAR 公式の Web ページ（README 2-1）で行います。3 枚の絵を 1 つの `.mind` にまとめてあり、どの絵をかざしても同じ内容が出るようにしています。

MindAR は 2024 年 1 月の 1.2.5 が最後の版で、A-Frame 1.4.2 との組み合わせで動作確認されています。だからこのデモはその 2 つを固定しています。

### model-viewer（モデルビューア）
Google が作った、**3D モデルを表示して「AR で見る」ボタンを付けられる HTML タグ** `<model-viewer>` です。デモC で使っています。

「AR で見る」を押すと、ブラウザではなく **スマホ標準の AR ビューア**（Android は Scene Viewer、iPhone は AR Quick Look）が開きます。標準ビューアは床を自動で見つけてモデルを置いてくれる反面、**こちらで作った画面（説明文やボタン）を重ねることはできません**。だからデモC のページは「AR に入る前」に説明を全部書いています。

iPhone の AR Quick Look は usdz しか読めないので、`ios-src="…usdz"` で usdz を渡します。model-viewer には glb から自動で usdz を作る機能もありますが、テクスチャが落ちやすいので、自分で変換したものを渡しています。

### three.js（スリージェイエス）
ブラウザで 3D を扱うための土台のライブラリ。A-Frame も model-viewer も内部では three.js を使っています。このデモで直接使っているのは `tools/usdz-convert.html` だけで、glb を読む部品（GLTFLoader）と usdz に書き出す部品（USDZExporter）を借りています。

### qrcode / qrcode-generator
QR コードを作るライブラリ。`tools/make-qr.mjs`（パソコンで PNG を作る）は `qrcode`、ページの中でその場で QR を描く処理（トップページの PC 表示と印刷ページ）は `qrcode-generator` を使っています。

## 4. 実行環境の言葉

### Node.js / npm / npx
- **Node.js**: JavaScript をブラウザの外（パソコンのターミナル）で動かすためのソフト。`tools/` のスクリプトはこれで動きます
- **npm**: Node.js 用の部品（パッケージ）をインストールする道具。`npm install` でこのプロジェクトに必要な部品が入る
- **npx**: 部品をインストールせずにその場で実行する道具。`npx serve .` で簡易サーバを立てるのに使う

### ffmpeg
動画・音声を変換する定番のコマンドラインツール。`make-video.mjs`（動画作成）と、`make-voice`（mp3 化）で使います。**無くても代替手段があります**（動画はパラパラ表示、音声は wav / m4a のまま）。

### ターミナル
コマンドを打ち込む黒い画面。macOS は「ターミナル.app」、Windows は「PowerShell」または「Windows ターミナル」。この docs で `$ node …` のように書いてある行は、ここに打ち込みます（`$` は打たない）。

### 環境変数
コマンドに渡す「設定値」。`SITE_URL=https://… node tools/make-qr.mjs` のように、コマンドの前に `名前=値` を書いて渡します。

### シード（乱数の種）
ランダムに絵を作るとき、「同じ数字を渡せば毎回同じ絵になる」ようにするための数字。`make-markers.mjs` でマーカーを作り直したいときにこの数字を変えます。
